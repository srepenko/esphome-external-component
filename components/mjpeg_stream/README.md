# mjpeg_stream — MJPEG-потік на екран ESP32-P4

Отримує MJPEG по HTTP (наприклад, go2rtc `api/stream.mjpeg`) і декодує кадри апаратним JPEG-декодером ESP32-P4 в окремій задачі. Кадр можна показати як зображення LVGL або вивести напряму в кадровий буфер.

Можливості:
- кілька потоків (`MULTI_CONF`); відкладений старт; дії `mjpeg_stream.start` / `mjpeg_stream.stop`; тригери `on_frame`, `on_connected`, `on_disconnected`;
- `direct_draw`: кадр повертається PPA на 270° (для `lvgl: rotation: 90`) і пишеться прямо в кадровий буфер, оминаючи LVGL; кути заокруглюються кольором фону;
- `exclude`: зони біля верхнього й нижнього краю кадру, куди відео напряму не пишеться. Там кадр малює LVGL (`bg_image`), тож напівпрозорі кнопки й написи поверх відео не перетираються.
- `set_exclude_owner(i, lv_obj)`: зона діє, лише поки віджет-власник видимий. Коли плитку сховано, відео малюється напряму й там, без зайвої перемальовки LVGL.

## Швидкість виведення

Для дисплея MIPI-DSI кадр повертається PPA одразу в кадровий буфер дисплея: блоками стовпців, в обхід зон-виключень і без очікування (`PPA_TRANS_MODE_NON_BLOCKING`, черга 32). Проміжного буфера повороту, копіювання процесором і окремої пересилки DMA2D через `draw_pixels_at` більше немає.

Виміряно на JC8012P4A1 для кадру 656×384 з 8 зонами-виключеннями (час основного циклу на кадр):

| Спосіб | мс/кадр |
|---|---|
| поворот у буфер + `draw_pixels_at` (як було) | ~36 |
| PPA у кадровий буфер, з очікуванням | ~15 |
| PPA у кадровий буфер, без очікування (за замовчуванням) | ~1.6 |

`set_fast(false)` повертає старий спосіб (для порівняння).

## Налаштування й діагностика

- `set_view(x, y, sx, sy, radius, use_excl)` — де й у якому масштабі виводити потік (PPA, крок масштабу 1/16). Один «теплий» потік можна миттєво показати на головному екрані, у сітці (×15/16) чи на весь екран (×1.94), без перепідключення до джерела. Зони-виключення діють лише без масштабу й при `use_excl`.
- `set_excl_every(n)` — як часто LVGL перемальовує відео під віджетами в зонах-виключеннях: кожен n-й кадр (за замовчуванням 2, 0 — ніколи). Під напівпрозорими кнопками відео тоді оновлюється рідше, зате LVGL менше працює.
- Раз на 5 с (рівень DEBUG) у лог пишуться:
  - кадри/с і середній час виведення кадру;
  - для LVGL: кількість перемальовок і їхній середній та сумарний час на секунду, кількість і площа інвалідацій, найбільша область. За цими даними на панелі знайдено дорогі перемальовки: дугу термостата, анімації й тіні.

```yaml
mjpeg_stream:
  - id: gate_stream
    url: "http://go2rtc:1984/api/stream.mjpeg?src=gate_panel"
    width: 656
    height: 384
    max_jpeg_size: 131072
    direct_draw:
      display: my_display
      x: 8
      y: 8
      radius: 14
      background: 0x0B1117
      exclude:
        - {x: 0, y: 0, width: 190, height: 44}
```
